# 阅读体感指纹、运行时目标与校准门

当用户蒸馏小说的目的包括“后续原创作品读起来具有相近体感”，使用本参考。它修复一种常见失败：审计层准确识别了短段、人物声音、身体注意力和标题承诺，编译运行时包时却只留下跨题材通用技法。

## 三层产物

### 1. 审计层：`STYLE_FINGERPRINT.json`

使用`templates/STYLE_FINGERPRINT.json.template`。它记录可重算表层分布和需人工判断的体验坐标：

- 句长、段长、分位数、短/长段比例、对白段比例、问号/省略号密度；
- 页面主要注意力落在身体、关系、行动、谜题、制度、环境或内省中的哪几类；
- 不同中性POV角色的句法、误读方式、身体/物件注意力和压力泄放；
- 标题承诺、章尾功能和说明密度；
- 各指标在动作、对白、关系、调查、过渡等场景中的变化。

指纹可以带作品范围和审计信息，但不得用少数名场面代替全书分布。平台换行、OCR和翻译会影响数值，必须记录限制。

### 2. 运行时层：两个来源隔离文件

从指纹编译：

- `READER_EXPERIENCE_CONTRACT.md`：保留主导阅读承诺、注意力预算、POV声音坐标、关系/身体节拍、幽默降域、标题和说明上限；
- `STYLE_TARGETS.json`：保留可机器复核的中性范围。

两者不得包含作品/作者身份、定位、引文、专名、独特比喻、人物映射或事件顺序。中性数值分布和抽象体验坐标本身可以进入runtime，因为它们不能恢复来源文本。

### 3. 项目层：`state/STYLE_CALIBRATION.md`

每个新项目记录样章接受和三章稳定性。默认策略是`sample-1-then-3`：

1. 第一章先作为`DRAFT / NOT COMMITTED`交付，让用户判断体感；
2. 用户接受后提交第一章；
3. 再完成前3章并检查跨场景稳定性；
4. 通过后才将`Bulk writing unlocked`设为`yes`。

用户可以明确要求跳过，但普通的“写20章”不是放弃校准的明示。记录豁免及风险。

## 目标分级

- **hard**：越界通常表示明显漂移，阻止交付；场景确有必要时必须在章节记录解释。
- **target**：期望范围；越界触发定点检查和一次聚焦修订。
- **human-only**：注意力优先、人物误读、标题承诺等不能可靠自动判定的项目。

不要把平均数变成逐段配额。章级目标负责页面分布，场景合同负责局部变化。若来源在不同场景分布明显不同，应为场景族建立范围，而不是强迫所有章节同一数值。

## 建立安全范围

1. 先用完整正文或代表性章节计算全书与分区统计；
2. 比较opening/middle/late和holdout，确认稳定性；
3. 目标区间应覆盖真实波动，不以单一均值作硬线；
4. hard范围比目标范围更宽，只拦截明显漂移；
5. 样本不足、平台换行污染或场景方差过大时，将指标降为diagnostic或human-only；
6. 词汇信号只能使用普通语义类别和通用词，不得把罕见来源用词清单带入runtime。

## 注意力预算优先于句子仿形

先判断每章把读者注意力放在哪里，再判断句段是否达标。若参考体验以关系/身体为主，而原创大纲连续数章把大部分拍数给程序、调查或制度，即使段长完全相同仍会严重偏离。

蓝图中必须写：

- 主导注意力；
- 支撑注意力；
- 不可反客为主的说明/支线；
- 标题承诺的读者欲望；
- 当前POV应如何误读、推断或泄压。

## 可重复统计

运行：

```sh
python3 scripts/style_metrics.py profile <chapter-or-files...>
python3 scripts/style_metrics.py compare --targets <STYLE_TARGETS.json> <chapter-or-files...>
```

统计只辅助定位。PASS不证明文学效果；FAIL也可能来自特殊高潮或说明章。机器结果必须与读者体验合同、场景功能和人工判断合并。

## 运行时回归

正式发布v2包前至少测试：

1. 单章能明显体现主导阅读承诺；
2. 同一项目连续3章仍保持段落分布、声音和注意力中心；
3. 调查/说明场不会把支撑类型变成全书主类型；
4. 标题能承诺主要读者欲望；
5. 去除runtime文件后，盲评能观察到目标特征显著下降（ablation）；
6. 来源隔离扫描仍为零泄漏。

跨题材测试继续保留，但不再允许它单独证明体感忠实。一个包若能迁移到所有题材却失去原本的阅读承诺，应标为`BLOCKED`或重新编译。
