# 交付、发布与版权边界

## 最终产物

- `INDEX.md`：Skill 分类、触发摘要、关系和推荐组合；
- `CRAFT_REPORT.md`：面向创作者的结构、技法、文风和声音报告；
- `COPYRIGHT_REPORT.md`：来源、引用、专名泄露、文本重合和人工复核结果；
- `skills/`：仅包含通过测试的自包含子 Skills。

`CRAFT_REPORT.md` 按创作问题组织，不按章节逐一复述。它不能成为原著的替代文本。

## 发布清单

交付前逐项确认：

1. 来源和版本信息一致；
2. 全书各结构区段均被处理；
3. 证据定位仍能回到原文；
4. 核心文风和声音结论经过 holdout；
5. 每个子 Skill 只有一种 kind；
6. 每个子 Skill 通过路由、执行、迁移和原创性测试；
7. 输出目录不含源小说、规范全文或 OCR 临时文件；
8. 报告没有密集引用或逐章替代性复述；
9. 生成样稿不含原作专名、独特表达或可识别情节映射；
10. 作品、版本和译者归因写清楚；
11. `COPYRIGHT_REPORT.md` 的发布决定为 `APPROVED` 且没有未解决问题。

任一项无法确认时，标记 `BLOCKED` 或 `NEEDS REVIEW`，不要发布。

## 引用原则

- 默认保存定位符、哈希和简短释义；只有核验确有必要时才保留极短引文。
- 引文要注明位置，不能把多个片段拼成原作的替代版本。
- 项目内部的长度限制不等于法律许可或安全港。
- 公开发布前，由发布者确认具体来源、引用语境和再分发权利。

## 创作边界

生成用途只能面向全新的小说项目。不要：

- 续写原作、补写番外或未出版章节；
- 复用原作人物、世界观、地名、专有设定或核心关系；
- 把原作情节逐点换名搬运；
- 要求“精确复制”或“无法分辨”的作者声音；
- 复制独特比喻、标志性句法、台词或大段文本。

把风格转换为中性、可观察的参数，例如“冲突段落逐步缩短句长”或“少用情绪命名，多用人物与物体的交互”。作者姓名只用于来源审计。

## 安装生成的 Skills

安装前询问目标宿主和范围。只复制 `skills/<slug>/`，并保留它自身的 `SKILL.md`、元数据、最小证据索引和测试记录。

不要安装：

- 小说原文或规范全文；
- 候选池；
- 内部账本中的核验短摘；
- 未通过测试的子 Skill。

安装后用一条正例和一条兄弟诱饵确认宿主能够正确加载和路由。若用户只要 Git 仓库产物，不擅自写入用户级配置目录。
