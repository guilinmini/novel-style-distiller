# 交付、发布与版权边界

## 最终产物

- `INDEX.md`：Skill 分类、触发摘要、关系图与推荐组合；
- `CRAFT_REPORT.md`：面向创作者的结构、技法、文风和声音报告；
- `COPYRIGHT_REPORT.md`：来源、引用、重合扫描、专名泄露和人工复核结果；
- `RELEASE_DECISION.json`：机器可读的发布决定、阻断项和逐文件重合结果；
- 仅包含通过测试的 `skills/` 子目录。

`CRAFT_REPORT.md` 按创作问题组织，不按章节逐一复述。它不能替代阅读原著，也不能通过密集剧情复述重建整部小说。

## 发布审计

交付前逐项确认：

1. 源文件哈希未改变；
2. 所有 chunk × extractor 已覆盖；
3. 所有证据定位仍有效；
4. 所有核心风格结论经过 holdout；
5. 所有 Skill 声明唯一 kind；
6. 所有 Skill 通过路由、执行、迁移和防复制测试；
7. 输出目录没有源小说或临时全文副本；
8. 报告没有密集连续引用或逐章替代性复述；
9. 生成样稿通过确定性重合扫描和人工独特性复核；
10. 版本与译者归因写清楚。
11. `RELEASE_DECISION.json` 的 `approved` 为 `true`、`blockers` 为空，且每个生成文件的 overlap 结果通过；结果中的源文件和样稿 SHA-256 必须与当前文件一致，修改样稿后必须重跑。

## 引用原则

- 默认保存定位符、哈希和释义；只在核验确有必要时保留极短引文。
- 引文必须明确标记、注明位置，不得拼接成原作的替代版本。
- 项目设定的字符预算只是内部护栏，不等于法律许可或“安全港”。
- 用户计划公开发布 pack 时，要求其自行确认来源、引用和发布权利。

## 创作边界

本 Skill 的生成用途是全新的小说项目。不要：

- 续写原作、补写番外或未出版章节；
- 复用原作人物、世界观、地名、专有设定或核心关系；
- 把原作情节逐点换名搬运；
- 要求“精确复制”或“无法分辨”的作者声音；
- 复制独特比喻、标志性句法或大段文本。

把风格转换为中性的可观察参数，例如“冲突段落逐步缩短句长”“叙述者少用情绪命名而多写物体交互”。作者名只用于来源审计。

## 安装生成的 Skills

在复制前询问用户目标宿主与范围。只复制自包含的 `skills/<slug>/`，其中保留最小 `evidence-index.json`，但不要复制源文本、候选池或原文核验片段。安装后用一条正例和一条兄弟诱饵验证宿主的加载与路由，并确认来源画像能从 evidence index 返回定位与证据释义。

若用户只需要 Git 仓库产物，保留构建目录即可，不擅自写入用户级配置目录。
