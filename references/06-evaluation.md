# 压力测试与验收

把评测分成四道独立闸门：蒸馏忠实度、Skill 路由、执行质量、原创性与迁移性。任何硬失败都不能被平均分抵消。

## 盲测隔离

测试执行者只能看到：

- 当前子 Skill；
- 用户 prompt；
- 必要的原创故事状态；
- 全包其他 Skill 的 `name + description`。

不要提前提供 case 类型、oracle、阈值或主流程评价。测试完成后再对照预期判卷。生成型用例建议运行 3 次并保留每次结果。

结果写入 `test-results.json`，人类可读摘要写入 `test-results.md`。失败和未完成测试同样保留，不能只把 `metadata.json` 手动标成 `passed`。

## 最小路由集

- 4 条明确正例；
- 2 条不含 Skill 标题关键词的隐式正例；
- 2 条完全无关诱饵；
- 3 条最近邻兄弟 Skill 诱饵；
- 1 条组合或边界题。

测试时让执行者在整个 Skill pack 中选择 `primary`、`secondary` 或 `abstain`，不要只问“是否触发当前 Skill”。

### `source-profile`

追加：

- 至少 1 条来源证据忠实度测试；
- 至少 1 条作品、版本或译本归因边界测试；
- 生成任务必须路由到 `transferable-technique` 兄弟 Skill 或拒绝；
- 作者角色扮演、原作续写和长引文请求不得通过。

### `transferable-technique`

追加：

- 至少 1 条跨题材迁移题，并累计覆盖 3 种相距较远的题材；
- 至少 1 条原创性压力题；
- 至少 1 条来源画像分析诱饵，确保不会抢占分析任务。

## 硬失败

以下任一情况直接失败：

- 虚构或错误的证据定位；
- 违反关键剧情事实或角色知识边界；
- 无标记跳头或越权进入非焦点人物内心；
- 泄露原作人物、地名、世界观专名或独特表达；
- 连续复刻三个具有辨识度的原作情节节拍；
- 出现明显的大段原文重合；
- `source-profile` 和 `transferable-technique` 职责混用；
- 不相关诱饵或兄弟 Skill 诱饵误触发。

## 建议阈值

| 维度 | 验收 |
|---|---|
| 关键剧情事实 | 100% |
| 主要人物一致性 | ≥ 0.92，关键事实 100% |
| POV 合规 | ≥ 0.97，越权内心描写为 0 |
| 路由 precision / recall | ≥ 0.95 / ≥ 0.90 |
| 路由 top-1 | ≥ 0.92 |
| 跨题材迁移 | 至少 3 种题材，成功率 ≥ 0.85 |
| 语气/声音盲评 | 总体 ≥ 4/5，核心维度 ≥ 3.5/5 |
| 原创性与诱饵 | 100% |

这些是项目验收建议，不是数学真理。样本不足时应降低置信度，而不是伪造精确统计。

## 原创性检查

生成样稿交付前逐项检查：

1. 搜索原作人物、地点、组织、物件和其他专名；
2. 对照剧情图，确认没有把原作事件逐点换名；
3. 检查是否连续复用三个辨识度高的情节节拍；
4. 检查独特比喻、台词、标志性句式和长片段重合；
5. 将可疑处改写为中性机制，而不是只替换名词；
6. 在 `COPYRIGHT_REPORT.md` 记录检查范围、发现和处理结果。

宿主若具备文本搜索或相似度工具，可以辅助筛查，但工具分数不能替代人工判断。即使表面重合很低，可识别的人物、世界观或情节复制仍然失败。

## Ablation

对可迁移 Skill 至少做一次有/无 Skill 对照：

1. 用同一原创输入生成 baseline；
2. 加载 Skill 后再次生成；
3. 盲评目标特征是否明显增强；
4. 检查剧情、人物、POV 和原创性是否退化。

如果 Skill 不能稳定改变目标特征，它只是解释文档，不是可执行 Skill。

## 发布条件

```text
无硬失败
AND 每个交付 Skill 通过自身测试
AND 所有诱饵、兄弟混淆、证据与原创性测试通过
AND 其余维度达到约定阈值或明确披露低置信度
```

修复后重跑相关完整测试集，不能只重跑失败用例。

## 运行时风格包测试

正式发布 `runtime-style-pack/` 前追加：

1. **隔离测试**：全文搜索来源身份、专名、locator、引文和来源路径；任一泄漏都是硬失败。
2. **契约执行测试**：用三个互不相关的原创题材验证 always-on 常量、场景模式和强度旋钮都可执行。
3. **场景差异测试**：同一原创项目分别写动作、对白、内省、过渡和高潮片段；检查风格稳定但表面节奏不机械相同。
4. **三章漂移测试**：连续生成至少三章，后两章只能读取 runtime pack 与项目状态；盲评核心维度是否仍在契约范围。
5. **状态优先测试**：制造风格偏好与人物事实、POV 或时间线冲突，确认系统保留 canon 并调整局部表达。
6. **项目路由测试**：项目专属 writer Skill 应命中写章、续写和修订请求；摘要、来源分析和另一项目写作请求不得误触发。
7. **验收门测试**：交付草稿后状态不得变化；接受后才应同步更新章节记录、当前状态、时间线和线程。

每章记录 pack ID、版本、使用的场景模式和漂移检查结果。项目锁定版本改变后必须重跑三章漂移和状态优先测试。
