# 证据验证与筛选

## 通用硬门

候选必须全部通过：

1. **定位可复核**：每个证据 ID 能解析到当前源哈希中的有效位置。
2. **结论受证据支持**：核验片段展示的是所称模式，不是只在语义上相关。
3. **适用范围诚实**：明确它出现于哪些场景、POV、人物或结构区段。
4. **反证已扫描**：记录例外并缩小结论；不得隐藏不符合样本。
5. **可执行**：至少有一个可观察动作、一个完成标准和一个强度控制。
6. **可迁移**：移除原作专名后，机制仍可用于新题材。
7. **非复制**：不要求复用独特句子、比喻、角色关系或情节顺序。
8. **归因正确**：作品设计、译者语言、确定性统计和解释性判断分开标注。

## 分类证据门槛

### 文风、语气与对白

- 至少 3 个非重叠样本；
- 来自至少 3 个 chunk；
- 覆盖开端/中段/结尾中的至少两个区段；
- 至少 1 个 holdout 样本支持；
- 记录不适用的文本类型或明确反例。

### 场景与节奏技法

- 至少 3 个完整场景；
- 覆盖至少两个结构区段；
- 能说明入场状态、张力变化与退场效果；
- 不能只凭章节末一句判断整套节奏机制。

### 人物弧光

- 形成初态 → 压力 → 关键选择 → 代价/后果的证据链；
- 关键节点均有定位；
- 区分角色自我叙述和实际行为；
- 检查反向选择或没有改变的证据。

### 剧情架构

- 形成设置 → 升级/转折 → 兑现的链条；
- 至少一个明确因果连接，而非只有时间相邻；
- 伏笔与兑现必须存在可识别的信息或意象关系；
- 反转必须说明读者认知如何改变。

## Holdout 使用

验证者先冻结候选表述，再打开 holdout：

- 支持：增加一条独立证据；
- 限定：缩小条件或降低强度；
- 反驳：淘汰或重写候选；
- 未出现：不能自动视为反驳，但需要降低全书范围声明。

不得看完 holdout 后发明结论，再把同一 holdout 当作独立验证。

## 可迁移性测试

将候选改写为不含书名、作者、人名、地名和专有术语的规则，然后回答：

- 输入最少需要什么？
- Agent 要执行哪些动作？
- 输出中如何观察到目标效果？
- 调高或调低强度会发生什么？
- 哪些场景会失败或造成副作用？

无法回答的候选只留在分析报告，不生成 Skill。

## 筛选结果

`verified.jsonl` 保留完整验证记录和置信度；`rejected.jsonl` 保留候选原 ID、失败门、理由和可能的降级用途。常见降级用途包括剧情事实、例证、术语或报告注释。
