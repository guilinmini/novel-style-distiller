# 六路独立提取

## 独立性

让六个提取器共享 manifest 和必要事实账本，但不要共享彼此的候选结论。剧情、人物、叙事与场景提取器可读取其负责范围的完整文本；文风和声音提取器只能读取非 holdout 正文，并使用已移除 holdout 场景及其 tone/style 字段的 ledger 视图。独立扫描能减少“第一个标签决定后续所有观察”的锚定效应。

环境支持并行 Agent 时并行运行；不支持时串行运行六次，每次只加载对应 extractor。不要为了并行而牺牲完整文本覆盖。

## Map–Reduce

对长篇小说采用两步：

1. **Map**：逐 chunk 扫描，记录局部候选与证据定位符。
2. **Reduce**：在同一 extractor 内合并重复模式，保留所有非重叠证据和反例。

重叠 chunk 的同一段文本只算一处证据。Reduce 不能把“多次提到同一例子”误作跨场景规律。

## 六个职责

| 提取器 | 负责 | 不负责 |
|---|---|---|
| 剧情架构 | 因果链、结构分区、支线、反转、伏笔兑现 | 句法和措辞 |
| 人物弧光 | 欲望、选择、代价、关系与状态变化 | 泛泛人物标签 |
| 叙事与信息 | POV、距离、可靠性、时间处理、信息分配 | 纯情节复述 |
| 场景与节奏 | 场景单元、张力波形、入退场、章节钩子 | 全书主题判断 |
| 语言文风 | 词汇、句法、节奏、段落、意象、感官与修辞 | 作者人格猜测 |
| 语气与对白 | 叙述姿态、温度、幽默/反讽、对白轮次与角色话语区分 | 只凭一句台词定型 |

## 候选格式

每行 JSON 必须符合 `schemas/candidate.schema.json`，核心字段是：

```text
可观察模式 → 使用条件 → 产生效果 → 运作机制
→ 可执行写法 → 强度旋钮 → 例外/失败模式 → evidence_ids
```

候选标题应描述技法，例如“冲突段落中的句长递减”，不要写“作者式节奏”。

## 证据要求

- 保存 locator、证据角色和极短核验片段；不要把大段原文复制进候选池。
- 为每条证据标记它是 `supports`、`qualifies` 还是 `contradicts`。
- 统计数字只能由确定性工具计算，并记录样本范围与算法。
- 对“不出现某现象”的结论，记录扫描范围，不能把没注意到当作不存在。
- 每个 extractor 必须主动提交反例，不允许只收正例。

## 覆盖矩阵

在 `PIPELINE_STATE.json` 维护 chunk × extractor 矩阵。所有 chunk 都必须完成剧情、人物、叙事与场景四路扫描；非 holdout chunk 还必须完成文风与声音两路扫描，holdout 对这两路标记为 `withheld`。失败、仍为 `pending` 或上下文截断的必需 pair 必须重跑。
